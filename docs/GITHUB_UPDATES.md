# GitHub 在线升级（5.2.0）

更新源固定为 https://github.com/shiknevus/devmemstudio 。应用访问 GitHub Releases 的 `releases/latest` 接口，仅接受 `v主版本.次版本.修订号` 或不带 `v` 的正式版本，不安装 draft、预发布或旧版。不需要把 GitHub token 放入客户端；本版适用于无需认证即可下载的发布文件。

## 使用

1. 5.1.0 及更早版本先手动升级到 5.2.0：关闭程序，保留 `registers.json`，换入新版 EXE。
2. 点击窗口右下角版本号旁的“检查更新”。程序启动 5 秒后也会后台检查，发现新版才展示更新窗口；失败写入系统日志。可取消勾选“启动时检查更新”。
3. 更新窗口显示当前版本、最新版本、更新包大小和更新说明（按 Markdown 渲染）。右下角主按钮随状态切换：“检查更新/重新检查”→“下载更新”→“重启并升级”；下载时显示进度和“取消”。
4. 校验完成后点击“重启并升级”。先完成或取消正在进行的读写、文件传输、串口连接和 bit 打包任务。连续采样、日志流与设备连接在关闭时停止。
5. 更新工具等待应用与启动器退出，原子替换外层 EXE，并重新启动。EXE 目录必须可写；不可写时使用发布页手动升级。

下载位于 `%LOCALAPPDATA%\DevmemStudio\updates\download-<随机目录>\`。安装前临时 EXE 位于用户启动的 EXE 旁，旧文件备份为 `<原EXE主名>-<旧版本>-backup.exe`（重名时追加 8 位随机标识），双击即可运行旧版。不用 `.bak`：公司透明加密会加密 PowerShell 生成的 `.bak`，改回 `.exe` 也无法运行（5.2.2 及更早版本升级时仍会产生这种 `.bak`，需用解密后的内容另存）。安装结果写入下载目录的 `result.json`；失败会显示说明。`registers.json`、组件定义、主机指纹和日志不会被发布包覆盖。

源码运行可以检查和下载，不能覆盖 Python 或运行库缓存里的 EXE。发布版通过 `DEVMEMSTUDIO_LAUNCHER` 定位外层文件，新增 `DEVMEMSTUDIO_LAUNCHER_PID` 让更新工具同时等待外层进程。

## 发布新版

1. 同步修改 `devmem_studio/__init__.py` 与 `assets/version_info.txt` 中的版本，例如 `5.3.0`。
2. 执行 `build_exe.bat`，所有检查通过后得到：
   - `dist/DevmemStudio.exe`
   - `dist/DevmemStudio-5.3.0-win64.zip`
   - `dist/DevmemStudio-5.3.0-win64.zip.sha256`
3. 在仓库的 Releases 页面创建正式 Release，标签为 `v5.3.0`，填写说明并上传 ZIP 和校验文件（`artifacts/release_github.py` 会同时上传两者）。此操作需要维护者自行发布；本地构建不会上传 GitHub。**校验文件必须上传**：API 受限时客户端只能靠它校验。
4. 旧版客户端检查后应显示 `5.3.0`，下载安装验证成功后可人工清理旧 EXE 备份。

ZIP 必须只包含 `DevmemStudio/DevmemStudio.exe`。校验文件内容为 `SHA256  ZIP文件名`。优先使用 GitHub 资产返回的 `sha256:` digest；无 digest 时读取同名 `.sha256` 文件。没有有效校验信息时拒绝下载更新。

## 第一版边界

- HTTPS 使用 Python 标准库，遵循系统代理设置并验证服务器证书。打包保留 `_ssl.pyd`、`libssl-3.dll` 和 `libcrypto-3.dll`。
- GitHub 请求超时 15 秒，连接级错误（代理/CDN 偶发断开 TLS 握手等）自动重试 3 次；下载总时限 30 分钟，单包上限 512 MiB。点击取消或关闭窗口立即生效：卡住的请求在后台自行超时退出，其结果被丢弃，已下载的临时文件随之删除。404 提示未发布正式版，可打开发布页手动下载。
- 匿名 API 每个出口 IP 每小时 60 次，公司 NAT 下多人共享容易耗尽。API 返回 403/429 时改为解析 `github.com/<仓库>/releases/latest` 的跳转得到版本号（不占 API 额度），按固定文件名下载 ZIP，大小取 `Content-Length`，校验只用 `.sha256` 文件；此时更新说明需在发布页查看。5.0.0 及更早的 Release 没有 `.sha256`，走此路径会拒绝下载。
- 安装工具使用 Windows PowerShell 5.1，通过隐藏的更新进程执行；重启的应用正常显示。受组织策略阻止 PowerShell 时需手动升级。
- 等待已知旧进程最多 120 秒；替换锁冲突最多重试 30 秒，不强制结束其他实例。
- 替换失败保留旧程序；新版启动失败或启动后 3 秒内以非零状态退出时尝试恢复并启动旧版。此检查不保证后续业务运行正常，运行后才发生的故障可直接运行保留的 `-backup.exe`，或把它改回原文件名回退。
- 保留成功下载目录、安装结果及旧版备份供排查，不自动清除这些文件。应用运行库缓存仍沿用原有清理规则。
- 检查、下载和安装均有本地回归覆盖。实际 GitHub 联网结果与最终构建记录见本版验收记录。
