## 已确认并修复的问题

| 优先级 | 缺陷与影响 | 修复 |
| --- | --- | --- |
| P1 | 基地址正则会取到注释中的旧 `PL_CFG_BASE_ADDR`、名称相似的其它宏；`REG_SPACE_BIAS(20'h800 + 20'h200)` 会被截断为 `0x800`，可能读写错误地址。非法十进制常量还会抛出异常中断导入。 | 忽略注释，匹配完整且名称精确的基地址宏；偏移必须是完整常量。无法解析的偏移跳过并警告，不把表达式前缀当地址。支持基地址大写 `'H`。 |
| P1 | SFTP 下载直接打开最终文件，连接中断时已有日志被截断成半成品；第一次下载失败也会留下看似有效的文件。 | 在目标目录写临时文件，传输成功后用 `os.replace` 替换；失败清理临时文件，原文件保持不变。离线下载使用相同策略。 |
| P2 | 串口打开时已停在 `Password:` 会把 `stty -echo` 当密码；最后等待窗口收到的 `login:` 未处理；等待密码时的断线异常被吞掉，可能误报就绪。 | 先完成所有提示检测，再进入登录状态；直接处理密码提示并等待 shell。错误凭据、超时和断线均失败退出，不报告已连接。 |
| P2 | 配置中的数值型地址能通过十六进制解析，却在 GUI `QLineEdit.setText` 处导致启动异常，数值本身的进制也存在歧义。 | 非字符串地址恢复安全默认值，避免猜测进制。 |
| P2 | `remember_password` / `remember_serial_password` 的字符串 `"false"` 被当成真值，仍可加载或保存明文密码。 | 仅显式 JSON `true` 允许保存/加载密码，其它类型按关闭处理。保留缺少旧 SSH 记忆标志时的既有迁移逻辑。 |
| P2 | 损坏的组件覆盖表可能因非对象类型、缺少/非字符串名称、非法位宽、负偏移、坏预设或位域导致 GUI 崩溃；坏覆盖表可能遮蔽正常内置类型。 | 加载及使用前校验结构，过滤无效寄存器、预设、位域及行为元数据；全无效的覆盖不替换内置定义；返回数据深拷贝，避免反向污染目录。 |
| P2 | `DemoSession.read/write(quiet=True)` 跳过参数校验，批量操作能接受越界地址、未对齐访问、非法位宽或溢出值，导致模拟验证假通过。 | 静默参数只控制日志，地址/写入校验始终执行；非法写入不修改模拟内存。 |
