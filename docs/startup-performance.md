# 启动速度验证（2026-10-07，4.2.0 单文件）

在本机用独立、不可见 Windows 桌面启动真实 EXE，以“创建进程 → 主窗口可响应 WM_NULL”计时。
每次测量都使用隔离的配置（1280×800 窗口、无设备连接）以及独立的 `LOCALAPPDATA` / `TEMP`，不读取或改写本机设置与密码。
首轮单列，后续 5 次取中位数；没有清空系统文件缓存，因此**不称作严格冷启动测试**。

## 新旧单文件同条件对比

同一时段交替运行，各 2 轮：

| 版本 | 体积 | 首次启动 | 后续 5 次中位数 |
|---|---:|---:|---:|
| 4.1.8 单文件（PyInstaller onefile） | 31.5 MB | 3.32 / 3.22 秒 | 3.17 / 3.02 秒 |
| **4.2.0 单文件（原生启动器 + 缓存）** | **19.6 MB** | 3.53 / 3.47 秒 | **0.744 / 0.758 秒** |

日常启动耗时降低约 **76%**。旧版每次启动都要把运行库解压到临时目录并在退出时删除；4.2.0 每个版本只解压一次。

## 首次启动的构成

- 解压 74.4 MB 运行库（LZMS）约 0.5 秒，SHA-256 校验约 0.03 秒，写入 110 个文件并原子改名，合计约 0.8 秒。
- 其余时间主要是杀毒软件扫描新释放的 DLL / PYD，以及程序第一次运行。另一次空缓存测量为 4.72 秒，首次耗时随杀毒扫描波动。
- 第二次起启动器只核对每个文件的大小与时间戳（不再计算哈希），然后直接运行；额外开销在测量噪声范围内。

## 启动路径上的其他优化

- SSH 库（paramiko / cryptography）不再在启动时导入，窗口出现后在后台预加载：`import devmem_studio.window` 由约 0.7 秒降为约 0.27 秒（源码环境，`-X importtime`）。
- 剔除未使用的 `invoke`（paramiko 的可选依赖，原先随 paramiko 在启动时加载约 0.28 秒）。

